# UTC offsets come from `date`, with a GNU then BSD fallback

A run's window and its local days must use the UTC offset in effect on each day, not today's: a window that crosses a DST change otherwise starts or ends an hour off, and the sweep and omitted-days check misplace a day's boundary. jq can't answer "what was the offset at instant T": `strflocaltime("%z")` returned the current offset for every date on macOS and `+0000` on Debian. So `scripts/tz.sh` asks `date`, trying GNU `date -d @T +%z` and then BSD `date -r T +%z`, and hands jq a table of each needed day's local midnight. This bends the "no GNU/BSD-only date flags" rule on purpose: both forms are tried, and when neither works the scripts stop (or say the check didn't run) instead of guessing. Everything else still does date math in jq.
